## 1. 目标

把原来单页的人口结构分析站，重构成一个**「一篇报告当门面 + 两个工具子页」**的小站。

- **首页 `/`**：一篇能吸引大众读完的报告（6 屏）。这是门面，KPI 是「愿意往下滚 + 点进子页」，不是「讲完」。
- **子页 `/population`**：原来那个人口结构仪表盘（年龄金字塔、播放、情景、消费热点）。
- **子页 `/marriage`**：新增。结婚趋势明细（年度、季度、省份、离结比）。
- **README**：改成封面（大图 + 一句话 + 三个入口）。

### 一条主线

```
结婚（当年）→ 出生（滞后约 1 年）→ 幼儿园/小学（6 年）→ 劳动力（20 年）→ 养老（60 年）
```

首页讲整条链，子页面各管一段。**结婚是出生人口的先行指标**，这是两个子页能放在一起讲的逻辑基础。

### 受众顺序

1. **先给大众**：不管你是谁，第一屏就要看懂。
2. **再分三个视角**：想买房的 / 关心人口的 / 看投资的。各自一节，各自深链到子页。

### 视觉

统一采用小样 **c（清爽仪表盘风）**：
- 浅灰底 `#f3f4f6`，白色卡片，圆角 16px，柔和阴影
- 主色蓝 `#2563eb`
- 与现有 Vue 3 + Tailwind 4 + daisyUI 5 最接近，落地成本最低（2–4 小时）

参考小样：`mockups/c.html`

### S4 三个视角（每个约 200 字 + 1 图）

- **想买房的**：婚房高峰在 31 岁。31 岁人口 2018 年达峰 2595 万，2025 年 1677 万，2030 年 1385 万。婚房需求指数 2030/2020 = 0.578，同期总人口 0.978。深链 → 人口结构（消费热点：婚房 31 岁）
- **关心人口的**：结婚数领先出生数约一年，是所有人口指标里最靠前的信号。2026 前三季继续负增长。深链 → 结婚趋势
- **看投资的**：11 个消费热点各自挂在一个年龄上（公寓 26 / 婚房 31 / 改善房 42 / 装修 46 / 大学费 51 / 汽车 53 / 医疗 60 / 养老 65 / 旅行 70 / 药物 77 / 养老院 84）。队列一动，需求就挪。深链 → 人口结构（热点图）

## 5. 数据

### 管线

```
data/source/marriage_rates.xlsx
  → scripts/marriage_xlsx2csv.py（openpyxl，扫表判块，不写死行号）
  → data/marriage_quarterly.csv   year,quarter,marriages_wan
     data/marriage_annual.csv     year,marriages_wan,divorces_wan,divorce_marriage_ratio
     data/marriage_provinces.csv  year,province,marriages_wan,first_marriage_wan,remarriage_wan,divorces_wan,divorce_rate_permille,divorce_marriage_ratio
     data/marriage_meta.json
  → scripts/csv2json.mjs（补 BOM/CRLF、空值→null）
  → web/public/data/*.json
```

- xlsx→CSV 只本地跑，**CSV 进 git**；CI 跑 `pnpm data` + `scripts/validate_data.mjs`。
- 校验断言：季度 39 行、年度 26 行、省 31 行、省合计 610.55 ± 0.1、季度合计 = 年度合计。

### 六个数据地雷（必须规避）

1. **省表实为 2024**：标"2025 年"的省表合计 610.55/351.30，与 2024 年全国一致。统一按 **2024** 标注，页面小字说明"表中『2025』与 2024 全国合计一致，按 2024 计"。
2. **离结比有三种算法**：表里同时存在 0.406（离婚对数÷结婚人数）、0.811（÷结婚对数，正确）、0.758（÷初婚人数）。全线只用 **对数 ÷ 对数**，图注写死公式。
3. **初婚/再婚是人数**：917.3 + 303.9 = 1221.2 万人 = 2 × 610.6 万对。初婚占比 = 初婚人数 ÷ (2 × 登记对数)。全国 75.1%、黑龙江 53.5%、广东 81.3%。
4. **投影数据缺 2021**：`full_population_projection.csv` 1951–2200 里唯独没有 2021。任何直读该文件都要先插值 (2020+2022)/2，否则 2021 掉 0。
5. **2025 离婚 274.3 反常**：比 2024 降 22%，同时结婚 +19.7%。可能是初步数或口径变化。标"初步数"，不写"婚姻稳定性回升"。
6. **投影 age0 ≠ 官方出生数**：不能当出生人口做相关或双轴。

### 明确不做的 8 种图

结婚数 + 结婚率双轴；省级绝对量排行榜（无分省人口算不了率）；"初婚离结比"省际比较；2026 前三季比 2025 全年；把 731 外推成反弹趋势；用 age0 当出生人口；"离结比升 = 离婚潮"；桑基图 / 生肖 vs 结婚数。

## 6. 技术方案

- **ECharts 注册集中**：`App.vue:20–30` 的 `use([...])` 搬到 `src/lib/echarts.js`，`main.js` 第一行 import。
- **`usePopulation` 改模块级单例**：state / computed 建在模块作用域，`ensureLoaded()` 幂等。切页不重 fetch、不重算 250 年 × 101 年龄。不装 Pinia。
- **图表 option 抽成 `buildOption(data)` 纯函数**：为将来预渲染 / 静态导出留口，避免 option 埋在 SFC 里。
- **修现有 bug**：播放器 `setInterval` 补 `onUnmounted` 清理；`App.vue:102` 的外层 `p-4` 容器移到 `AppShell`，避免双份 padding；`index.html` 的 `lang="en"` 改 `zh-CN`、`<title>` 改站名、favicon 改相对路径。
- **删除死文件**：`web/public/data/full_population_projection.json`（363KB，全仓无引用）。
- **不升级依赖**：Vite 8 / Tailwind 4 / ECharts 6 都很新，重构期只做结构，不碰版本。CI Node 固定 22（现在写的是 20，与 engines 不符）。
